## 1. 目標

做一個校內用的手機櫃查詢系統，讓職員快速知道：

1. **以學生為單位**：班別、學號、該生最後開門日期時間，以及最後使用的箱門。
2. **以箱門為單位**：A 至 G 各櫃，每一格目前／最後對應哪位學生、最後開門時間。
3. **以往記錄**：所有開門紀錄存入 PostgreSQL，可按學生或箱門查看歷史。

資料來源是內聯網開門日誌：

`http://10.127.7.200:17789/#/Logs/OpenLog`  
操作：在該頁用日期範圍搜尋，再「導出 Excel」，匯入本系統。

系統會記住**上一次成功匯入的日期**，下次只拉該日之後（含重疊緩衝）的紀錄，避免每次全量匯出。

不在內聯網時，不可假裝已同步；要清楚提示用戶連上校內網絡後再同步。

登入第一期：`admin` / `000000`。稍後改 Google 電郵登入，資料模型預留，今期不做 Google OAuth。

## 2. 已核實的限制

| 項目 | 結果 |
|------|------|
| 本雲端環境連 `10.127.7.200:17789` | **連線逾時**。公有雲（Railway、Vercel、GitHub Actions 等）**無法**直接打內聯網。 |
| OpenLog 頁面結構、Excel 欄位、登入方式 | **未知**。沒有樣本檔，也進不了該 SPA。 |
| 現有程式碼 | 空倉庫（只有 README 標題）。 |

因此：**自動「按導出 Excel」必須在能連到 `10.127.7.200` 的機器上執行**。網頁可以給校外看歷史資料，但**同步動作**一定要在內聯網發生。

## 3. 三種做法（取捨）

### 方案 A（建議）：校內一部永遠開機的主機，整套系統都放校內

一台校內 Windows / Linux 電腦或 NAS（能 ping `10.127.7.200`），用 Docker 跑：

- PostgreSQL
- Web 應用（畫面 + API + 同步工作）

職員在校內 Wi‑Fi 開系統。按「同步」時，主機向內聯網系統取 Excel、解析、寫入資料庫。

- 優點：學生資料不出校網；沒有 CORS；架構最簡單；符合「不在內聯網就提示」。
- 缺點：要有一部常開機器、備份、以及（如需校外查看）VPN 或稍後再加反向代理。

### 方案 B：雲端網站 + 校內同步代理

網站與 PostgreSQL 放 Railway／同類雲端；校內另跑一個很小的 **sync agent**（或職員瀏覽器在校內按同步，由 agent 代抓）。

- 優點：校外也可查歷史；主機壞了網站仍在。
- 缺點：學生開門紀錄出校；要維護兩處；內聯網帳號不能只放在雲端。**不建議作第一期**（個資、複雜度）。

### 方案 C：只有人手上傳 Excel

網站任何地方都可開；職員自己在 OpenLog 導出 Excel 再上傳。系統仍記 last fetch date，用作畫面提示「請匯出此日期之後」。

- 優點：不依賴自動化爬頁；第一期最快。
- 缺點：每次要人手；容易漏同步。可作 **後備途徑**，不應是唯一途徑。

**第一期建議：A + C。** 校內主機自動／一鍵同步；失敗時可人手上傳同一格式 Excel。方案 B 留到「必須校外查詢」再做。

## 4. 需要的伺服器與軟件

第一期 **一部校內主機** 即可，不是三台實體伺服器。

### 4.1 主機條件

- 與 `10.127.7.200` 同一內網（或路由可達），永久開機或上課時段開機。
- 建議：4 GB RAM、20 GB 磁碟、有線網絡。
- 系統：Windows 10/11 或 Ubuntu 22.04+ 皆可；用 Docker Desktop / Docker Engine。
- 固定內網 IP 或 DHCP 保留，例如 `http://10.127.x.x:3000`。
- 防火牆只開給校內；不要把 PostgreSQL 端口暴露到互聯網。

請確認這部機器是哪一種（見文末問題 1）。

### 4.2 Docker 服務（同一主機）

| 服務 | 角色 | 對外 |
|------|------|------|
| `app` | 網頁、登入、查詢 API、同步工作（解析 Excel、寫庫） | 校內 `:3000`（或 `:443`） |
| `db` | PostgreSQL 16 | 只聽 `docker` 內部網絡 |

不需要獨立 Redis／Elasticsearch。同步是偶發批次，不是高併發。

### 4.3 可選（第一期不做）

- 反向代理（Caddy/Nginx）+ TLS：若要用域名。
- 校外 VPN。
- Playwright 獨立 worker：僅當內聯網沒有可用 HTTP API、必須模擬按「導出 Excel」時才需要。屆時仍跑在同一 `app` 容器或旁邊多一個 `sync` 容器。

### 4.4 技術棧（建議）

| 層 | 選擇 | 原因 |
|----|------|------|
| 網頁 + API | Next.js（App Router）+ TypeScript | 單一程式；之後加 Google 登入容易 |
| UI | 專業、多色彩、**藍色主色**；`en` / `zh-HK` 對照 | 符合你的設計要求 |
| 日期 | `yyyy-mm-dd`，時間 `HH:mm:ss`，時區 `Asia/Hong_Kong` | |
| ORM | Prisma | PostgreSQL 遷移清楚 |
| 資料庫 | PostgreSQL 16 | 你指定 |
| Excel | `exceljs` 或 `xlsx` | 解析導出檔 |
| 同步（優先） | 直接呼叫內聯網 **HTTP API**（從瀏覽器開發者工具對出來） | 比模擬 UI 穩 |
| 同步（後備） | Playwright 開 OpenLog → 填日期 → 按導出 | API 不明或有驗證碼時 |
| 認證第一期 | 單一管理員帳密，密碼雜湊（bcrypt），**不明文存 `000000`** | 介面登入名仍是 admin |
| 認證第二期 | Google OAuth（Workspace / 指定電郵白名單） | 預留 `users.email` |

不用 OpenRouter / Jina / fal.ai：本系統是查詢與同步，沒有 AI 生成。

## 5. 資料如何流動

```
內聯網 OpenLog (10.127.7.200:17789)
        │  僅當同步程序跑在校內主機
        ▼
  探測內聯網是否可達（短 timeout）
        │
        ├─ 不可達 → API 回傳 intranet_unreachable
        │            畫面提示：請連接校內網絡後再同步
        │
        └─ 可達 → 用 last_success_date 組成日期範圍
                  導出 / 下載 Excel
                  解析列、正規化箱門編號、去重
                  寫入 open_events
                  重算學生最後狀態、箱門最後狀態
                  更新 sync_state.last_success_at
```

人手上傳走同一套解析與去重，不經過內聯網探測。

### 5.1 日期範圍規則 〔假設〕

- 記 `sync_state.last_success_open_date`（日誌裡最後一筆開門日，不是電腦鐘）。
- 下次搜尋：`from = last_success_open_date`（重疊一天，防止時區／漏行），`to = 今天（香港）`。
- 第一次：`from` 由你指定（例如本學年開始 `2026-09-01`），或允許「全期匯出一次」。
- 同一事件用穩定指紋去重（時間 + 學號 + 箱門 + 開箱類型），重複匯入不加倍。

### 5.2 「最後使用 locker」規則（你已說明）

**不論開箱類型**（存入、取出、管理開啟等），該次開門都算該生「最後使用」的箱門，也更新該箱門的最後開門者／時間。

〔待確認〕取出後該格是否應顯示「空置」，還是仍顯示最後開門的學生？見問題 6。

### 5.3 不在內聯網時的提示文案（計劃）

- zh-HK：`未能連接校內手機櫃系統（10.127.7.200）。請確認已連接學校網絡後再同步。已保存的歷史紀錄仍可查閱。`
- en：`Cannot reach the school locker system (10.127.7.200). Connect to the school network and try again. Saved history remains available.`

若網站本身也只在校內，用戶在家會連不上網站；那時由瀏覽器／DNS 失敗處理。提示主要給：**網站開得到，但同步打不開內聯網** 的情況（例如主機暫時斷線，或誤把 app 放到雲端）。

## 7. 畫面範圍（今期只規劃，不實作）

中英對照：右上切換 `繁體中文（香港）` / `English`。日期 `yyyy-mm-dd`。藍色主色，輔以少量對比色（成功綠、警告橙、櫃別色帶 A–G）。

### 登入

帳號、密碼。錯誤不透露是帳號還是密碼錯。

### 首頁 — 兩個檢視（Tab）

1. **學生**  
   表：班別、學號、（姓名若有）、最後開門日期時間、最後箱門、最後開箱類型。  
   可搜班別／學號；可按班別、時間排序。  
   點一列 → 該生歷史。

2. **箱門**  
   先選櫃 A–G（卡片或分頁），再看該櫃每一格：箱門編號、學生班別＋學號、最後開門時間、類型。  
   點一格 → 該門歷史。

頁首顯示：最後成功同步時間、內聯網狀態（可達／不可達）、按鈕「同步內聯網」與「上傳 Excel」。

### 歷史頁

同一套篩選：學生／箱門／日期範圍／開箱類型。分頁。不做複雜報表。

- 學生自己查自己的箱

## 8. 安全（第一期下限）

- 密碼只存雜湊。
- Session cookie：`httpOnly`、`sameSite=lax`；校內 HTTP 時不能強制 `secure`（沒有 HTTPS）。
- 內聯網系統若需帳密，只放主機環境變數，不進 Git、不進瀏覽器。
- 同步 API 需已登入。
- 上傳 Excel 只接受 `.xlsx`／`.xls`，大小上限（例如 20 MB），在伺服器解析。
- 管理後台不做「刪改開門事實」；錯資料用重新匯入去重覆蓋。必要時只提供「清空本學年再匯」的管理動作（需你批准才做）。
